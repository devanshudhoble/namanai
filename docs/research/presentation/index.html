AI APM case study · Paytm Travel

Bol ke book karo

Say the trip once. Hear the real total. Never wonder where your money went.

A voice booking assistant for bus and train inside Paytm Checkin, for Hindi-first travellers.
Research, PRD-level scope and a working prototype with an MCP booking server.

Independent concept, not affiliated with Paytm. Prices and payments in the demo are sandbox.

NextFlights, cross-mode compare, proactive cancel alerts
OutItineraries, hotels, generic Q&A, bookings without the user's words
07 · AI architecture

The LLM understands. Tools decide. Templates speak.

Voice / text→Credential guard + PII redaction→Layered context (≤1,200 tokens)→Gemini → schema JSON→Server validation + rule overrides→MCP tools: search, fare rules, hold, UPI, reconcile, refund→Grounding validator→Reply + Sarvam TTS
  • MCP server: the same 9 tools and guardrails for app, voice, WhatsApp or any agent
  • In-code guardrails: no booking without the customer's own words; prices set server-side; idempotent retries
  • Graceful degradation: offline understanding engine if the LLM is slow or down
08 · Success metrics & evaluation

Ship only if completion goes up and guardrails stay clean

North starBooking completion rate, Hindi-locale cohort (session → ticket)
SecondaryTime to book · turns to options · payment-step recovery · refund contacts / 1k bookings
GuardrailsPIN/OTP to model = 0 · ungrounded ₹ = 0 · wrong bookings ≤ control · p90 ≤ 2.5 s
Offline eval30-utterance Hinglish NLU set · 22 + 5 + 16 automated tests passing

A/B test: 50/50 Hindi-locale users, after "final total upfront" ships to both arms. Kill if no lift in 4 weeks or any credential leak.

09 · Demo

Live prototype: 2 minutes

  1. One Hinglish sentence → options in one turn
  2. Read-back and explicit "yes" → fare hold → UPI
  3. Bank timeout → retry on same order, no double charge
  4. "Money debited, seat sold out" → reconciled → full auto-refund
  5. User says their PIN → blocked by the credential guard
  6. Same booking through the MCP server from another client

Sandbox inventory and payments. The guardrails and decision logic are real.
